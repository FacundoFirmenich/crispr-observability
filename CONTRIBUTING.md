# Contributing a reproducible scientific check

Contributions can improve the method, evidence navigation, laboratory operations,
format adapters, accessibility or documentation. Start with an issue describing
the exact scientific or software behaviour affected. Existing scientific feedback
forms already accept computational failures and omissions.

Provide the source commit; OS/runtime or browser; the smallest shareable authentic
input or a clearly labelled software fixture; exact command or control sequence;
expected and observed behaviour; and the affected claim, event and denominator.
Remove credentials and protected human data before posting. Do not upload private
manuscripts or source data without permission.

Preserve historical observations, failed checks and decision timing. A new rule
receives a new contract/version rather than rewriting old results. A format adapter
must document coordinate, orientation, missing-value and metadata-loss conventions.
Add a regression check when changing scientific behaviour. Use the visual palette
in `docs/VISUAL_STYLE.md` and preserve third-party licence notices.

Open a pull request with the problem, resulting behaviour, validation and evidence
boundary. Reports of independent reproduction should identify the actual analyst,
execution and source scope; repository activity alone is not scientific validation.
