# Native execution adjudication

The comparative campaign preserves execution failure, implementation repair and event comparability as separate questions. The pinned versions are CRISPResso2 2.3.4, ampliCan 1.32.1 and CRISPR-A upstream e5c6c8df1711df6de1f9c3c832ee297d5c48d18d. Complete archives are in release `comparison-evidence-43493655364`.

1. CRISPResso2: all nine fresh native jobs completed; acquired-record identity and observed-string projections pass.
2. ampliCan: all nine libraries completed in each of three assignment-anchor configurations. Exact sequence-family transitions preserve multiplicities and expose non-nested admission.
3. CRISPR-A initial execution: disabled-index basename collision. Distinct empty paths repaired staging without enabling self-reference or consuming a genome index.
4. CRISPR-A second execution: a non-rectangular return object could not be written as the original CSV. An export-only patch preserves the complete object as RDS and a long-form CSV without changing calculations.
5. CRISPR-A export-compatible execution: nine variant stages complete; the final global heatmap fails because its sample-name file is absent. This failed whole-workflow status remains recorded.
6. Return-object audit: all three treated libraries violate the consumer's scalar count/type/IDs interface. The first counts 2, 4 and 1 coexist with 897, 1398 and 882 unique matching identifiers. Six controls satisfy the zero-count interface.
7. Typed-return intervention: all nine variant stages rerun on archived BAMs with unchanged matching criteria. Matching row counts are summed; type and IDs occupy explicit list fields. All nine objects pass the interface check, and all six control percentage tables remain byte-identical.
